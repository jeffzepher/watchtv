# WatchTV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成个人自用 WatchTV 的本地网站、服务器部署、Electron 客户端及 GitHub 提交。

**Architecture:** React 客户端通过同源 Node/Fastify API 聚合苹果 CMS 来源，纯协议逻辑独立共享。Electron 启动同一应用服务；服务器用 Docker Compose 运行网站与认证入口。

**Tech Stack:** TypeScript、React、Vite、Fastify、hls.js、IndexedDB、Electron、Docker Compose、Node 测试工具。

**Spec:** `docs/superpowers/specs/2026-10-21-watchtv-design.md`

## Global Constraints

- 个人自用；不做注册、多用户或云同步。
- 首版上限为 50 个源，并发请求最多 5 个，每源搜索时限 10 秒。
- 候选源不默认启用，不宣称已实测可播放。
- IndexedDB 保存个人数据，localStorage 保存设置和源配置。
- 仅 HTTP(S) 上游，禁止访问私网、回环与保留地址；校验 DNS 结果及每次重定向。
- Electron 使用上下文隔离、禁用 Node 集成和沙箱，不关闭浏览器安全策略。
- 不向 Git 提交环境文件、私钥、访问密码、用户数据或部署产物。
- 公网部署使用访问认证；HTTPS 未就绪时经 SSH 隧道验收，不公开明文登录入口。
- Docker Hub 已观察到超时，部署必须先验证实际镜像获取路径。

## Review Focus

1. 不同年份同名影片不能误合并：核心层测试覆盖。
2. 慢源及旧搜索不能覆盖新搜索：后端与 UI 测试覆盖。
3. 导入的坏 URL、DNS/重定向到私网不能变成代理入口：网络层测试覆盖。
4. 手机 Safari 播放和 HLS 相对地址不能因桌面成功而漏检：播放器与清单测试覆盖，设备未实测则注明。
5. 登录失败、会话过期和配置导出不能泄漏密码：认证与导出测试覆盖。

## Task 1: 协议与安全网络层

**Files:** 根目录 `package.json`、`.gitignore`、`tsconfig.json`；`packages/core/src/{types,sources,applecms,grouping}.ts`；`apps/server/src/upstream.ts`；`tests/{core,upstream}.test.ts`。

**Interfaces:** `Source {name,url,enabled}`；`parseSources(input: unknown): Source[]`；`parseVod(item: unknown, source: Source): Video`；`groupVideos(videos: Video[]): VideoGroup[]`；`safeFetch(url: URL, options): Promise<Response>`。

- [ ] 写测试：拒绝非 HTTP URL、超限导入、坏 JSON；解析多线路和坏剧集；不同年份不合并；私网 IPv4/IPv6、DNS 与重定向绕过被拒绝。
- [ ] 配置 workspace 和测试脚本，运行测试确认因未实现失败。
- [ ] 实现协议与固定 DNS 连接的网络层，限制响应体、请求时限和重定向次数。
- [ ] 运行核心与网络测试，全部通过后提交。

## Task 2: 后端、认证和媒体通道

**Files:** `apps/server/src/{app,search,auth,media,index}.ts`；`tests/{server,auth,media}.test.ts`。

**Interfaces:** `createApp(options): Promise<FastifyInstance>`；`POST /api/search` 返回 SSE；`POST /api/detail`；`POST /api/sources/test`；`POST /api/subscriptions/import`；`POST /api/login`；`POST /api/logout`；`GET /api/session`；`GET /health`；签名票据限定的 `GET /api/media`。

- [ ] 写模拟源集成测试：单源失败不影响其余源、最多 5 个并发、10 秒超时、客户端断开中止上游、分页、坏响应。
- [ ] 写认证测试：错误密码、限流、会话过期、Cookie 属性、跨站请求拒绝；媒体测试覆盖相对清单 URI、密钥 URI、Range、重定向检查与流式取消。
- [ ] 运行测试确认失败，实施后端路由、静态服务、安全头和认证。密码及签名密钥仅从环境读取，日志不记录 Cookie 或凭证。
- [ ] 测试全部通过后提交。

**Interfaces:** API 适配 Task 2；`saveProgress(record): Promise<void>`、`listHistory(): Promise<HistoryEntry[]>`；按源 URL 与影片 ID 生成稳定标识。

- [ ] 写状态测试：新搜索取消旧搜索、同源分页追加、空源引导、进度恢复、坏备份拒绝、恢复收藏与历史。
- [ ] 实现深色桌面侧栏与手机导航；首页、增量搜索、详情、线路与选集、加载/空/错状态。
- [ ] 实现原生 HLS 优先和 hls.js 回退、MP4、倍速、下一集、换源匹配、进度保存与恢复；播放失败明确提示。
- [ ] 实现来源编辑、启停、探测、候选源手动添加、订阅导入与备份导出；导出不含服务端密码。
- [ ] 加入仅缓存应用外壳的 PWA；验证登录页和 API 不被 service worker 缓存，注销后敏感界面不残留。
- [ ] 运行测试、类型检查、生产构建；用可控媒体完成浏览器闭环，检查桌面与手机尺寸、键盘与错误状态。真实源检测独立记录。通过后提交。
