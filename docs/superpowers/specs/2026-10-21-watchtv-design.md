# WatchTV 首版设计

日期：2026-10-21

## 目标与已确认需求

项目仓库：https://github.com/jeffzepher/watchtv 。当前本地目录与远程仓库均未提供现有产品代码。

面向个人自用，参考 LibreTV 的使用流程，独立实现电脑、手机浏览器可用的影视搜索与播放网站，随后复用网页核心封装 Windows Electron 客户端。用户已确认需要配置多个来源并聚合搜索，也希望协助寻找候选来源。

首版不提供账号、多人管理或跨设备自动同步。手机桌面入口采用 PWA，不提供 Android/iOS 原生安装包。收藏与进度为各设备独立保存，提供配置与用户数据导入导出。

## 技术方案与取舍

选择 React + TypeScript + Vite 构建客户端，Node.js + Fastify 提供 API 与生产静态文件服务，采用 npm workspaces 管理 web、server、desktop 与共享类型/源适配器。

相比直接改造 LibreTV，独立实现能明确模块边界并减少历史功能负担；相比 Next.js 一体应用，独立网页构建产物更容易在 Electron 里复用。本项目不需要服务端渲染与 SEO。

网页通过同源后端访问第三方 API，以处理跨域、超时与响应校验。Electron 在主进程内启动仅监听回环地址、使用随机端口的同一应用服务，加载本地页面，不依赖公网部署。手机浏览器连接用户运行的网页服务；安装在电脑上的 Electron 不自动成为手机访问入口。

## 首版范围

1. 首页：品牌、搜索入口、继续观看、收藏入口及源配置提示；没有来源时显示引导，不用虚构影片填充。
2. 搜索：多个启用源并发查询，逐步显示结果；支持取消旧请求、每源超时和独立错误状态。
3. 结果：按规范化片名、年份与内容类型分组；信息缺失或冲突时保留独立条目，不仅凭片名强行合并。
4. 详情：海报、简介、来源、播放线路与剧集；缺失字段有清晰回退。
5. 播放：原生 video + hls.js，支持 HLS 与浏览器支持的 MP4、选集、倍速、全屏、自动下一集、断点续播。优先原生 HLS；其他浏览器使用 hls.js。
6. 换源：选择其他来源，只有剧集名称可明确匹配时才恢复同集进度；无法确认时要求重新选集，避免切错集。
7. 个人数据：收藏、观看历史、当前集与秒级进度，使用 IndexedDB；设置和源配置使用 localStorage。正常播放节流保存，暂停及页面隐藏时补存。
8. 源管理：名称、API URL、启停、编辑、删除、单源与批量检测、JSON 导入导出。
9. PWA：manifest、图标与应用外壳缓存，支持浏览器允许时添加主屏幕；HTTPS 部署或 localhost 才提供完整安装能力。不缓存视频分片，不承诺离线播放。
10. Electron：Windows 窗口、开发运行与安装包构建配置，复用网站的搜索、播放和数据逻辑。

直播/IPTV、下载、广告分片修改、爬取详情页、TVBOX Spider 引擎、推荐榜单接入、自动更新与云同步留到后续。

## 数据源协议与候选清单

首版适配苹果 CMS JSON API：搜索使用 `?ac=videolist&wd=<关键词>&pg=<页码>`，详情使用 `?ac=videolist&ids=<id>`。处理 `vod_play_from` 与 `vod_play_url` 中的线路、剧集分隔符；只接受可识别的 HTTP(S) 媒体 URL，不执行来源返回的 HTML 或脚本。

支持 LibreTV SourceList 的 `sources` 数组与裸源数组，按规范化 URL 去重。导入时校验版本、字段、数量与 URL；不支持的直播项、Spider 或 TVBOX 配置给出明确说明，不假装导入成功。首版上限为 50 个源，并发请求最多 5 个，每源搜索时限 10 秒；分页由用户触发继续加载，不扫描全库。

## 组件与数据流

- `apps/web`：响应式页面、播放器、浏览器数据存储、PWA。
- `apps/server`：源请求代理、订阅读取、并发搜索与 SSE 结果推送、生产页面服务。
- `apps/desktop`：Electron 生命周期、本地服务启动、窗口与打包。
- `packages/core`：源类型、苹果 CMS 解析、结果归组、配置校验，不依赖 UI 或 Electron。

搜索流程：网页发送关键词和已启用源配置 → 后端验证目标 → 按并发限制请求 → 逐源推送成功/失败 → 网页增量归组。取消搜索时关闭流并中止上游请求。详情仅请求选定源，历史条目同时保留源 URL 与影片 ID，避免不同源 ID 冲突。

媒体优先直连；确需跨域代理时，仅允许已验证来源的受限媒体请求。HLS 代理须重写子清单、分片及密钥 URI，支持相对地址和 Range，逐跳验证重定向目标，流式转发并随客户端断开中止。无法安全兼容的来源显示原因并允许换源，不关闭浏览器安全策略。

## 界面方向

默认深色影院风格，突出搜索、海报与继续观看。电脑使用侧栏导航与多列海报；手机使用紧凑页头与底部导航，详情、选集和源设置适配窄屏。页面覆盖加载、空结果、无来源、部分失败和播放错误状态。播放器优先保证手机横竖屏与触控操作。

## 安全与部署

网页首版面向本机或可信局域网，公网部署需额外访问控制，不默认公开启动。第三方内容作为不可信数据处理，简介按文本渲染，配置导入限制大小与条目数量。网络入口限制请求体、并发、时限与响应大小；URL 限制 HTTP(S)，阻止回环、内网、保留地址、DNS 重绑定与重定向绕过，防止代理访问内部服务。网页 API 不允许任意跨域调用。

Electron 使用 `contextIsolation: true`、`nodeIntegration: false`、沙箱与最小 preload；拒绝未知导航和弹窗，不向页面暴露任意文件/进程能力。本地服务使用启动令牌与 Origin 校验；桌面关闭时结束服务。

浏览器版提供 Node 启动与 Docker 部署说明。首版不依赖付费服务或数据库服务器。Windows 安装包能否在当前环境完成构建，取决于 Electron 二进制与打包工具下载是否被网络策略允许；受阻时保留可构建配置并明确报告，不能以网页构建通过替代安装包验证。

## 验收

- 源解析、配置校验、归组、剧集解析以固定夹具进行单元验证；包含畸形数据与相同片名不同年份。
- 后端通过模拟源验证并发上限、取消、超时、部分失败以及 URL 安全限制。
- 用可控样例媒体验证搜索 → 详情 → 选集 → 播放 → 历史续播完整流程；来源不可用时仍可重复验证核心功能。
- 验证桌面与手机尺寸无横向溢出，关键操作支持键盘与触控，空状态和错误状态可理解。
- TypeScript 检查、相关测试与生产构建通过；真实源检测与样例测试分开报告。
- Electron 验证本地服务生命周期、加载、受限导航与 Windows 打包；未能执行的检查明确列为未验证。

## 实施顺序

先做共享协议、模拟源与后端，再完成网站搜索/详情/播放闭环与个人数据，然后补 PWA、源导入导出和响应式检查，最后接 Electron 并验证安装包。具体任务与执行步骤在设计评审通过后编写实施计划。

## 已确认的部署环境与补充约束

用户已授权本地部署、部署到其服务器，以及提交到 GitHub 仓库。服务器为 Ubuntu 24.04 amd64，Docker Engine 与 Compose 已安装、服务已启动；Docker Hub 的测试拉取超时，不能依赖其直连可用。SSH 凭证存放于用户本机 SSH 目录，不进入项目、镜像或 Git。

公网自用版本增加单密码登录；密码通过服务器环境文件设置，使用带期限的 HttpOnly 会话 Cookie、登录速率限制和同源校验。HTTPS 优先；当前未提供域名，初次远程验收通过 SSH 隧道进行，公开 HTTPS 入口需在确认域名或可用的受信任 IP 证书后启用，不在明文公网 HTTP 中传递登录凭证。

部署先验证可达的镜像仓库。若常用仓库均不可达，在本地可用构建环境生成镜像后通过 SSH 导入服务器；不得假定本机已安装 Docker。只有网站健康检查、认证与实际容器运行验证通过才报告远程部署成功。Electron 安装包验证与网站部署分别报告。
